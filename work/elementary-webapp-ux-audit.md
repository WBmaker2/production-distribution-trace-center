# 초등 학습자 UX 기준선 감사

## 감사 범위

- 감사일: 2026-08-31
- 대상: `production-distribution-trace-center`
- 모드: `full`
- 기준선: 기존 리디자인 결과를 중복 작성하지 않고, 후속 학습자 패널·문구·회복·반응형 수용성을 추가 확인
- 사용 도구: 실제 로컬 Vite preview + Codex in-app Browser, `$elementary-webapp-ux-orchestrator`, `$playwright` 브라우저 규칙, `$impeccable` audit/craft-floor 규칙

## 학생 패널 기준선

실제 학생 연구가 아닌 일관된 휴리스틱 기록입니다.

- 주 페르소나: 초5–6 서윤(10–12세). 제목·라벨을 먼저 훑고, 왜 그런 결과인지 근거를 기대하는 학습자.
- 가드레일: 초3–4 준호. 짧은 지시를 처리하고 한 번 틀리면 다른 방법을 시도하는 학습자.

| 단계 | 보이는 단서 | 행동/결과 | 학습자 관점 신호 |
|---|---|---|---|
| 입구 | 생산·가공·운송·판매·소비, 시간·비용·잃음 토큰, `경로 추적하기` | CTA를 바로 찾고 첫 활동으로 이동 | 목적은 추측 가능하지만 `잃음`의 뜻은 첫 화면에서 바로 풀리지 않음 |
| 관찰 | `지금 할 일`, 목표, 상품 장면, 토큰 범례 | 단계 카드를 읽고 다음으로 이동 | 토큰 범례는 도움이 되나 `잃음`은 자연스러운 교과 낱말이 아님 |
| 조립 | 남은 카드, 만든 경로, 연결 검사 | 일부러 판매를 먼저 놓고 검사한 뒤 다시 만들기 | 오류 이유는 이해 가능. 카드 조작은 버튼으로 회복 가능 |
| 조건 변경 | `검수된 조건 중 딱 한 가지만`, `예상해 보세요` | 라디오를 고르면 결과 합계가 즉시 보이고 비교 버튼을 누름 | 예측 전에 결과를 보게 되어 지시와 행동 순서가 살짝 어긋남 |
| 판단 | `판단 기록하기`, 근거/자료 선택 | 빈 입력으로 기록한 뒤 다시 정하기 | `기록에 통과`는 학생이 이해할 상태 이름보다 평가 시스템처럼 들림 |
| 완료/전이 | 유통 기록, 다음 미션/전체 기록 버튼 | 마지막 완료 후 명확한 학습 takeaway를 찾음 | 기준선에서는 마지막 완료 문구·다음 학습 행동이 부족함 |

## P0–P3 이슈 장부

### EDU-UX-001

- Severity: P2
- Title: 320px에서 body 최소 너비가 실제 표시 영역보다 큼
- Path/state: 입구 및 큰 글자 설정, 320×800
- Persona/viewport: 초5–6 서윤 / 320×800
- Observed action/result: 브라우저 측정에서 `clientWidth=305`, `bodyWidth=320`, CTA `right=308`; 시각적으로 우측 스크롤바와 겹칠 수 있음
- Root-cause hypothesis: `src/styles/app.css:7`의 `body { min-width: 320px; }`가 세로 스크롤바가 차지하는 폭을 고려하지 않음
- Learner impact: 좁은 기기에서 CTA·문장 오른쪽 여백이 줄고 200% 글자 확대 시 잘림 위험이 커짐
- Proposed change: body 최소 너비를 제거하고, 실제 콘텐츠가 viewport client 영역 안에서 줄어들게 함. 320px 회귀 측정을 추가함
- Verification: 320×800 및 큰 글자에서 body/client/scroll width와 CTA bounding box 재측정
- Status: open

### EDU-UX-002

- Severity: P2
- Title: 학생 언어에서 손실 지표 이름이 `잃음`으로 표시됨
- Path/state: 입구, 관찰, 기본 경로, 전후 비교, 판단 기록
- Persona/viewport: 초5–6 서윤 / 320·375·1280
- Observed action/result: 앱은 `잃음 토큰`을 쓰지만 README·index 메타·구현 계획은 `손실 토큰`을 사용함
- Root-cause hypothesis: 내부 `lossTokens`를 그대로 학생용 낱말로 번역하면서 문서의 교과 용어와 분리됨
- Learner impact: 낯선 명사와 화면/문서 간 불일치 때문에 같은 비교 항목을 다시 해석해야 함
- Proposed change: 학생 화면·검수된 미션 문구를 `손실`로 통일하고 첫 범례에서 `상품이 줄어드는 정도`로 풀이함. 내부 필드명·숫자·판정 규칙은 보존함
- Verification: 모든 정상/오답/완료 상태에서 `손실` 표시, `잃음 토큰` 잔존 여부, token/null 계산 회귀 확인
- Status: open

### EDU-UX-003

- Severity: P2
- Title: 조건 변경 지시의 예측 순서와 즉시 결과 표시가 어긋남
- Path/state: 조건 변경 → 전후 비교
- Persona/viewport: 초5–6 서윤 / 1280 및 375
- Observed action/result: 라디오를 고른 즉시 `적용 후 합계`가 표시되며, 다음 `전후 비교 확인` 화면에서 같은 결과가 반복됨
- Root-cause hypothesis: 조건 선택 상태와 비교 결과를 한 화면에서 동시에 보여 주도록 구성됨
- Learner impact: “먼저 예상”할 시간이 줄고, 선택·적용·비교의 차이를 구분하기 어려움
- Proposed change: 선택 직후에는 고른 조건과 다음 행동만 안내하고, 수치 결과는 비교 화면에서 한 번만 보여 줌. `조건 하나를 고르고 무엇이 달라질지 먼저 생각`하는 문구로 정리함
- Verification: 선택 전 CTA disabled, 선택 후 안내 표시, 비교 버튼 후에만 전후 표와 diff 표시
- Status: open

### EDU-UX-004

- Severity: P2
- Title: 마지막 미션 완료 뒤 학습 takeaway와 다음 행동이 약함
- Path/state: 마지막 REPORT에서 `전체 기록 마치기` 클릭 후
- Persona/viewport: 초5–6 서윤 / 375·1280
- Observed action/result: 기준선 report는 같은 `판단의 흔적` 제목을 유지하고 다음 버튼만 사라짐
- Root-cause hypothesis: `finished` 상태가 화면 제목·요약·전이 문구에 연결되지 않음
- Learner impact: 활동이 끝났는지, 무엇을 기억하고 다음에 무엇을 해 볼지 확인하기 어려움
- Proposed change: 완료 상태에 `모든 경로를 살펴봤어요`, 시간·비용·손실을 함께 비교하라는 takeaway, 주변 상품 경로를 적어 보는 다음 행동을 추가함
- Verification: 마지막 미션 완료 직후 완료 제목·takeaway·다시 시작/인쇄 행동을 같은 viewport에서 확인
- Status: open

### EDU-UX-005

- Severity: P1
- Title: 오답 뒤 이전 자료 선택이 남아 자연스러운 재시도가 막힘
- Path/state: 자료 부족 미션 `DECIDE` → `BEGIN_REVISION` → `DECIDE`
- Persona/viewport: 초5–6 서윤 / 1280×900
- Observed action/result: `날씨 기록 자료`를 잘못 고른 뒤 `한 번 다시 정하기`로 돌아가 `운송비 자료`를 골라도 두 자료가 함께 기록되어 최종 판단이 오답으로 남음
- Root-cause hypothesis: `BEGIN_REVISION`이 이전 `selectedDataKeys`·`selectedEvidenceKeys`를 새 판단 답안으로 초기화하지 않음
- Learner impact: 올바른 자료를 다시 골라도 핵심 미션을 자연스럽게 완료할 수 없고, 학생이 이전 선택을 직접 해제해야 함
- Proposed change: 수정 시작 시 자료·근거 선택을 비우고, 첫 판단 기록과 경로는 보존함
- Verification: 같은 오답→수정→정답 흐름에서 최종 자료가 `운송비 자료` 하나이고 판단이 accepted인지 확인
- Status: discovered during recovery probe / fix in progress

### P0/P1 판정

- P0: 0건. 개인정보·안전·외부 전송 위험 증거 없음.
- P1: 1건(EDU-UX-005). 핵심 오답 회복 경로가 정답 자료 재선택만으로 완료되지 않아 수정 전 수용 게이트를 막음.
- 우선순위: EDU-UX-005를 먼저 고친 뒤 EDU-UX-001부터 004까지 같은 시나리오로 수정·재검증.
